# 携程网页查询：报价归属与有限搜索

## 本轮修复

1. **报价整体选择**：`OfferDetails.matched_quote` 携带价格、实际航段、来源响应 URL
   和查询批次。解析时复制数据，结果组装不再从变化中的响应列表另选航班。
   保存前检查价格一致性并再次核对请求条件。
2. **先校验再选低价**：普通单程、往返、多程的结构化候选都检查实际日期、
   起终点、舱位和航司；直飞要求仍有效。未知舱位不默认为用户要求的舱位。
   往返须检查去程和返程，全程航司/舱位条件逐段执行。
3. **查询代际隔离**：请求开始时记录代际；新搜索后，旧请求及尚未完成 JSON 解码的
   旧响应均不能加入当前列表。直接结果页、表单提交、舱位 URL 修正都开始新批次。
4. **撤销不可靠负缓存**：携程与飞猪都无法证明当前响应包含全量库存，因此不读写
   无航线负缓存。携程只返回部分路线或页面无结果时记录未知，可恢复重试。

## 普通监控的行为变化

- 低价日历即使日期相符，也不足以证明航线、舱位、航司和产品归属。本轮选择保守策略：
  **不再用日历或纯 DOM 文字兜底保存普通监控报价**，而不是推测未确认的请求字段。
- 若仅有上述数据，任务报告 `Ctrip quote unverified`；它表示信息不足，不表示没有航班。
- 网络行程匹配成功才保存新报价。旧报价不删除，也不自动重新标成有效。
- 机场码如 PEK、PKX、PVG、ICN 等与城市码不同的别名按指定机场匹配；
  BJS、SEL 等城市请求可匹配其机场。SHA、CTU 等兼有城市/机场含义的代码仍按城市处理，
  本轮不增加新的机场选择 UI 或全球机场字典。
- ISO 日期时间中的 `T` 分隔符也能解析；组合/未知舱位代码不再靠字母子串猜测。

## 甩尾任务兼容性

- 甩尾页面加载不依赖普通监控的“合格最低价”，避免提前过滤混合舱位路线。
  返回的原始候选继续由甩尾服务按首段/全程规则校验。
- 新携程任务中的 `search_inconclusive` 是可重试的失败检查点，历史表现记录为未知。
  有返回但不满足用户条件的具体报价，仍可单独保存有效路线证据。
- 携程查询指纹升级至版本 3。旧版任务请重新探索，不能沿用旧的“无结果已完成”检查点。
  飞猪仍用版本 2，原有恢复行为不变。
- 平台限流冷却仍保留；停用无航线负缓存并不意味着绕过平台频率限制。

## 仍然存在的限制

本轮不声称页面已加载全部库存，也不保证最低价、可出票或各平台票价口径一致。
普通查询的结构校验不等于完整票规/库存校验；历史数据仍需注意时效。
更严格的证据要求可能减少成功保存的结果，尤其是仅返回日历或文字的页面；
后续只有在确认独立字段证据后，才应恢复这些来源的可信报价能力。
未根据携程线上页面重新校准航班列表选择器，也未进行真实携程实测。
所有回归使用模拟响应，不需要平台账号或 API key。

## 后续：日期证据与渐进加载

日期验证不再从任意输入框、日历日期条或正文中的日期子串推断“已选中”：

- 读取可见且明确属于出发/返程的控件，以及明确标注的结果日期标题；
  隐藏输入、其他表单和日期条不算证明。打开的日期编辑器不算提交完成。
- 先收集证据再判定，正确输入不能覆盖错误结果标题或 URL 日期。
- 往返分别核对去程与返程；URL 中的第二个日期不能证明第一个日期。
- 完整年份优先，不能用月日子串忽略错误年份；仅显示月日时，需要其他明确的年份证据。
- URL 单独正确、正文为空并不足以确认页面日期。
- 普通查询若已选中完整、校验通过的网络行程，且页面没有明确日期冲突/打开的日期编辑器，
  可用该行程确认实际出行日期，记录 `matched_source=network_itinerary`、`ui_status=unknown`，
  不把无法识别的页面控件假装成已确认。
- 甩尾页面日期冲突和日期证据不足分别记录 `date_mismatch` / `date_unconfirmed`，
  均可重试，不表示没有航班。

结果等待不再一看到 `flightItineraryList` 就结束：

- 默认最多 12 次观察，相邻观察等待 1 秒；页面操作耗时另计，外层任务超时仍生效。
- 已有一批结果时仍观察后续变化、进行有界滚动，并等待航班相关请求及 JSON 解码结束。
- 到达底部、没有加载信号/相关待处理请求，且连续 3 次观察无变化，才记录 `quiet`。
  滚动卡住和达到等待预算分别记录 `scroll_stalled` / `wait_budget`。
- 同一代际、同一响应进度已经稳定时可复用等待结果，避免同一路径重复等待；
  新响应或新查询会重新检查。
- 报价和甩尾尝试记录 `loading_evidence`。所有分支的 `coverage_complete` 都为 `false`：
  **稳定窗口不等于平台已经返回全量库存。** 无结果负缓存仍保持关闭。

## 回归覆盖

`tests/test_ctrip_query_integrity.py` 包括：

- 错误/缺失舱位、航司、日期、错误 HTTP 状态，过滤后保留更贵但合格的报价；
- 城市与指定机场、往返返程日期、多程条件以及断裂航段；
- 后到响应不能把旧价格和新航班拼接，修改价格/条件后拒绝保存；
- 日历与未绑定页面价格不能被提升为可信报价；
- 请求跨批次和 JSON 解码跨批次，两种旧响应均被丢弃；
- 舱位 URL 更正开启新批次，甩尾加载不被普通查询筛选阻断；
- 甩尾未知结果不写负缓存、不生成路线负证据，并且恢复后会重查。
