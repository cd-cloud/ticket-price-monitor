# 国航分阶段接入

## 当前进度：P0 已读到真实单程票价产品，最终报价适配尚未完成

2026-10-30 更新：已按携程分层拆出编排、页面状态、稳定等待、解析与结果模块，
并接通独立网页实验任务。详见 [实验任务架构及携程对照](AIRCHINA_EXPERIMENT.md)。
下文的“不写价格数据库”指不写正式价格快照/甩尾结果；网页实验任务另有专用记录表。

2026-10-30 使用正常官网表单人工选择 PEK → SHA、2026-11-10、1 成人，
得到新版入口：

```text
https://www.airchina.com.cn/flight/oneway/pek-sha/2026-11-10
```

页面可见出发/到达机场、日期、1 成人和「选择航班」，随后出现「安全验证」
及「请点击上图中的」。用户手动完成验证后，已读取 16 个航班卡片：
经济舱 16 个、公务舱 16 个、超级经济舱 9 个、头等舱 2 个可见起价，共 43 项。
例如 CA1549，PEK T3 → SHA T2，16:30–18:45，经济舱 ¥600 起。
这只是该次采样的公开参考价，不代表当前库存或可出票价格。

官网明确标注「以下价格为每位成人旅客不含税票价」。
`providers/airchina_dom.js` 只读可见 DOM；`providers/airchina_parser.py`
同时校验 URL 和可见机场、日期、人数、行程类型、舱位列标题。
每个起价与同一航班行的航班号/时间/机场/舱位绑定，不读取日历或跨行补全。
当前只接受观察到的同日、单航班行结构；跨日、转机、共享多航班号、
缺失/冲突字段均不作猜测；航司筛选仅指营销航司，实际承运航司仍未知。

解析结果使用 `reference_fare` 而不是普通报价的 `price`，
明确 `tax_included=false`、`price_kind=starting_fare`、`total_price=null`，
列表参考价的库存/票价产品/可出票性均未确认；只输出诊断预览，不写价格数据库。
用户随后手动关闭乘机提示，已展开 CA1549 经济舱和公务舱：

| 舱等 | 产品/子舱位 | 每成人不含税基础票价 | 页面行李摘要 |
|---|---|---|---|
| 经济舱 | 超值特价 K | 600 | 20KG |
| 经济舱 | 特惠折扣 S | 930 | 20KG |
| 经济舱 | 优选折扣 V | 1300 | 20KG |
| 经济舱 | 基础折扣 U | 1830 | 20KG |
| 经济舱 | 经济全价 Y | 2150 | 20KG |
| 公务舱 | 公务折扣 R | 2880 | 30KG |
| 公务舱 | 公务 J | 8390 | 30KG |

这些是采样时的显示信息，不是价格承诺。具体产品使用 `base_fare`、
`price_kind=product_base_fare`，并标记 `fare_product_confirmed=true`；
`tax_included=false`、`total_price=null` 和 `bookable_confirmed=false` 不变。
网页显示的「预估优惠」单独记录，不扣减基础票价；
退改费仅保留原始「5%起」/「0%起」摘要，不推断完整票规。

重要：经济舱产品 DOM 有透明的 `cabinDetails_seatPlaceholder`「剩余0张」，
AX 与 innerText 都能读到，但不应被当成可见余座。采集器显式排除此占位；
这时余座为未知，而不是零。公务舱 R/J 真正可见的余座分别是 3/7，
仅记为 `displayed_seats`，仍不承诺最终库存。

新 `providers/airchina_products.py` 对同一航班行的展开舱等、产品名、
子舱位、基础票价做绑定；过渡加载、验证/提示遮挡、日期不一致、
跨行/跨舱等污染、冲突产品与未知子舱位组合均保守拒绝。
目前只校准以上两类舱等及已观察的子舱位组合，未验证其他组合。
暂无往返、联程、税费/结算总价样本。
未自动处理挑战/确认提示，未进入预订或支付流程。
首页日历曾显示价格，但**日历价不是指定航班报价**。这些观察仅证明该次会话
到达了查询页，不证明无会话直达、其他航线、往返或无人值守运行可用。

此前把“航班动态查询”作为机票联程能力依据是不充分的：动态和订票是不同功能。
后续以真实订票结果页为依据，不根据动态页推断是否支持中转/联程。

### 已实现

- 新版单程探测入口，明确机场码与日期校验；不把往返、多程、多人数悄悄降级。
- 独立 CLI `airchina-probe`，不添加监控任务、不启用 provider、不写价格数据库。
- 识别人工验证、HTTP 拦截、非预期页面；一次导航，不重发查询、不换后端绕过限制。
- 默认只保存白名单诊断字段，不记录原始 URL 查询参数、异常详情、cookies、
  网络响应、账号或 API key；不读取/解密任何平台凭据。
- 可显式等待用户自行处理页面、可显式保存本地可见文本/截图。
- 阻止旧的通用价格提取入口把国航日历价或无关数字写成报价。
- 离线回归测试。测试文本是合成场景，**不是国航真实报价样本**。
- 新增脱敏的真实公开列表样本 `tests/fixtures/airchina_visible_oneway.json`：
  2026-10-30 人工验证后，通过同一个只读 DOM 采集器取得；
  仅包含机场、日期、航班/时间、舱位列与不含税起价，不包含账号、cookies、
  请求头、网络响应、挑战内容或脚本。解析测试在真实样本上变异错误场景。
  原有 probe 测试文本仍是合成场景，不得混称真实查价测试。
- 新增 `airchina_expanded_economy.json` / `airchina_expanded_business.json`：
  同一公开航班的两种展开产品样本，不包含身份信息、会话或网络凭据。
- 显式 `--flight-no` 才展开一个航班的具体舱等，始终不点击预订；
  已展开不重复点击，等待期间仅有界读取 DOM，不重发搜索。

`airchina` 的正式报价 `has_handler=False`、默认禁用和不支持甩尾仍保持不变；
实验任务通过独立入口运行，不绕过正式查询准入。
已有携程/飞猪并行代码不受影响。没有伪造尚未观察到的官方响应字段/接口。

## 探测使用

用实际将来的日期运行（下面日期仅为本次测试样例，过期后需更换）：

```sh
python main.py airchina-probe --origin PEK --destination SHA --date 2026-11-10
```

允许自己在浏览器中处理验证/提示，并保存用于开发解析器的本地可见证据：

```sh
python main.py airchina-probe --origin PEK --destination SHA --date 2026-11-10 \
  --manual-wait-seconds 180 --capture-visible-page
```

单个航班产品查询（不点击预订）：

```sh
python main.py airchina-probe --origin PEK --destination SHA --date 2026-11-10 \
  --flight-no CA1549 --cabin economy --manual-wait-seconds 180
```

`--cabin` 当前只允许 `economy` / `business`。未指定 `--flight-no` 时仍只读列表。
这是本机项目浏览器的入口；应用内浏览器中完成验证不意味着项目 Chrome profile
也已通过，可能需要再次人工处理。不会复制 cookies 或验证凭据。

CLI 人工等待结束后重新分类页面；可读取时有界等待稳定 DOM，再关闭诊断上下文。
不会自动点击挑战或预订按钮。网页实验任务则等待显式人工继续信号。
默认使用项目配置的浏览器后端并强制有界面的浏览器；需要时可加 `--backend chrome`。
现有 `inspect-page --provider airchina` 也改走专用探测流程（采用配置中的航线；
仅接受单程 1 成人）。使用 `airchina-probe` 可避免改动配置中的监控航线。

- 输出：`runtime/airchina_probes/<唯一目录>/report.json`。
- 退出码 **2**：探测结束但查询能力尚未验证，不代表查价成功。
- `query_page_unverified` 也不是“已查到航班”，更不是“无票”。
- `reference_fares_observed` 表示读取了符合本次条件的可见不含税起价，
  仍不是正式查价成功。诊断报告 `reference_preview` 给出绑定行程的参考数据。
- `fare_products_observed` 表示 `product_preview` 已读取指定航班的具体票价产品，
  仍不包含税费总价或最终库存。退出码保持 2，不冒充完整查询能力已验收。
- 不操作官网的舱位/航司/中转筛选；`filters_applied=false` 指平台筛选未应用。
  参考解析器会在已读到的行中按舱位/营销航司筛选；仅支持单程 1 成人、
  `any` / `direct_only`，其他条件显式返回不支持。只采样，不代表全量。
- 可见文本/截图可能包含已登录账号信息，仅在显式开启 capture 后保存；
  应始终留在已忽略的 `runtime/`，不得提交 GitHub。分享样本前人工脱敏。
- 此命令不会自动提交运输提示确认、登录、验证或购票操作。
- 修改示例配置不会覆盖本机 `config.json`；探测本身不使用旧 URL 模板。

## 阶段验收门槛

### P0：固定航线查询

尚待完成：

1. 已取得单程起价及两类舱等的真实产品；仍需往返/无结果/报错与其他产品场景。
2. 专用航班卡片/结构化响应解析：将航班号、机场、日期、时间、舱位、人数、
   币种、税费口径和价格绑定在同一个报价中；不能依赖页面任意数字兜底。
3. 验证刷新、会话复用、日期切换、多人库存和验证码状态。未验证的条件显式拒绝。
4. 脱敏样本测试 + 少量人工核对通过后，再注册实验 handler；保持默认不加入并行。

不能取得可靠结果时停在此阶段，不把诊断入口包装成可用查价平台。

### P1：固定候选城市甩尾复核

以 P0 通过且取得完整 A-B-C 联程报价为前提：

- 查询 A→C 的联程结果并校验经 B；不得用两张单程票简单相加冒充联程报价。
- 验证两航段、跨日、营销/承运航司、混舱、机场衔接与含税口径。
- 独立进度、预算、断点和失败；人工验证暂停；无结果不视为全量无票。
- 仅候选城市，不假定官网有开放目的地能力。

### P2：可选三平台查询

以 P1 通过为前提：

- 新 API 使用 `providers: ["ctrip", "feizhu", "airchina"]`，
  兼容已有 `provider="both"` 的携程/飞猪历史任务。
- 由能力注册表生成平台多选 UI，不继续扩展 `both/three/all` 枚举。
- 人工验证继续操作按子任务定向，不再绑定携程一个平台。
- 国航会话、限流和失败与其他平台隔离；选择性续跑/重试保持各自检查点。
- 结果保留来源和价格口径，不跨平台错误去重、不直接宣称平台价差可比。
