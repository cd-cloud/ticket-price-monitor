# 甩尾查询工作区

## 本轮范围

只调整操作流程、结果归属读取和页面呈现，不改变平台检索、票价口径、
航段校验、频率限制、负缓存及首段/全程筛选规则。不新增前端运行时框架；
Bootstrap Accordion 只以本地编译 CSS 复用，构建依赖固定于 `package.json` 和锁文件。

## 折叠组件与展开布局

- 「报价与航班限制」「搜索范围」使用独立通栏卡片，不再让两个设置区共享网格行，
  展开任意设置都不会把另一个拉成大块空白卡。
- 复用 [Bootstrap Accordion](https://getbootstrap.com/docs/5.3/components/accordion/)
  的标题、箭头、边框、展开背景与焦点样式，版本为 5.3.8，MIT 许可保存在
  `static/vendor/LICENSE-bootstrap.txt`。只引入局部样式，不带入 Bootstrap 的全局 reset 或 JS。
- `tools/tail-accordion.scss` 限定 `.tail-ui-accordion` 作用域，`tools/build_tail_accordion.mjs`
  生成 `static/vendor/tail-accordion.css`。构建使用 `bootstrap@5.3.8`、`sass@1.107.1`。
- 保留原生 `<details>`、输入 ID、展开状态、原生校验和焦点恢复。标题与摘要是独立
  flex 项，长摘要可换行，窄屏不拆散标题，也不因 `nowrap` 产生横向溢出。
- 展开内容桌面三列、平板两列、手机一列；候选来源与摘要宽屏并排。
  手机展开表单的操作栏回到正常文档流，不吸底遮挡输入项。

### 查询

- 默认展示出发地、实际乘坐到哪里（例如北京 → 上海中的上海）、出发日期、平台。
  额外尾段属于购票组合，不代表用户最终要前往的城市；`origin`、`transfer`、`destination` 和 API 语义不变。
- 舱位、航司、时间、人数及查询价格上限位于「报价与航班限制」。
- 检索方式与候选城市位于「搜索范围」，飞猪检索方式不再混入票价筛选。
  预算位于独立的「高级控制」，摘要只统计当前平台实际生效的调整项。
  平台不支持的配置隐藏并禁用，保留切换平台前的输入值；开放/混合模式的请求仍使用原有预算语义。
- 保留数字预算语义：空白或 0 表示不限，补查次数 0 表示关闭，均有文字说明；
  本轮没有替换后端预算模型或额外增加预设搜索策略。
- 候选城市可搜索、选择搜索到的城市、清空、恢复推荐。手动选择不再被
  出发地、抵达城市、航司变化覆盖；新出发地和抵达城市仍排除。
- 只将固定白名单的表单字段和候选城市保存在浏览器 localStorage；
  不存储账号、API key 或运行结果。提交前仍需用户点击搜索。

### 当前任务

- 开始查询后折叠条件，运行期间禁用编辑/重复提交。停止不删除已保存结果。
- 每轮进度读取后刷新当前任务的保存报价；不是每轮重新查询平台。
- 显示当前状态、已查数量和已保存报价数；城市列表、排序依据和调用预算折叠。
- 开放/混合查询只显示已完成查询单元，不显示全库存百分比。
- 轮询超时/断网保留活动任务 ID 与结果，退避重连；不会把连接断开视为任务结束。
  已确认的 HTTP 404 单独提示「任务找不到」，不无限锁住页面。
- POST 响应丢失时只读检查后台最新任务，不自动重复 POST；服务器明确拒绝输入时
  允许修正表单。结果列表读取失败与任务状态读取失败分开显示。
- 继续、重试失败城市、重新查价、重新查询此任务根据任务状态显示。
- 可恢复任务的主按钮是「继续此任务」，沿用原任务条件；表单查询降级为次操作。
  表单与任务条件不同时显示「使用新条件查询」，不混用旧任务恢复和新查询语义。
  单平台和双平台任务区各最多一个主恢复按钮，重新查价等次级操作继续折叠。
- 活动任务与所选历史任务并存时，常显后台执行路线；切换所选任务立即刷新
  「下方结果另有所属」提示，不等待下一次轮询。

### 结果

- 「任务报价」按明确任务 ID 从 SQLite 检查点的 result_ids 读取，而不是用航线、
  日期或最近 N 条记录猜测归属。继续任务解析 checkpoint_job_id，包含已完成项。
- 「历史报价」读取跨任务保存数据。任务选择器提供最近 20 个任务；
  更早的报价仍可从历史列表分页读取。旧版任务没有检查点时不冒充本次结果。
- 结果标题显示所选任务的路线、日期、平台，不改成正在编辑的表单条件；
  「切换任务 / 查询条件」入口只重复任务状态，不再重复整条路线。历史模式明确是跨任务报价。
- 已有结果时压缩说明和任务区留白；已完成任务或浏览历史时突出「查看方案」。
  暂停、失败、等待验证仍优先原恢复动作，只有点击才滚动和移动焦点，不自动跳转。
- 读取接口兼容无 job_id 的历史模式，并增加 offset 分页：
  `GET /api/tail-discovery/results?job_id=...&limit=200&offset=0`
  返回 results、has_more、next_offset、job_id。不存在的任务返回 404。
  排序用 observed_at + id，筛选任务发生在 LIMIT 之前。
- 默认加载 200 条，可继续加载；明确说明列表筛选/排序只作用于已加载报价。
  正在运行时刷新会保留已加载页深度，并按 ID 去重，旧请求不能覆盖新视图。
- 多平台已加载结果提供「全部 / 携程 / 飞猪」快捷按钮，显示各平台已加载条数。
  快捷按钮与原平台筛选同步，清除筛选恢复全部；不发起新的平台查询。
- 状态分为「已校验且未过期」「信息待核实（未过期）」「已过期/时间未知」。
  不再在卡片展示启发式「高可信」或 raw `complete`，已校验也不表示可出票。
- 先按「我要乘坐」的首段分组，再按完整购票行程展示平台报价。完整多航段、
  航班号、机场和报价口径一致时，才将不同平台放在同一行程组；平台固定顺序，
  不展示跨平台最低价。不同尾段不是同行程平台价差，缺证据候选不被强行合并。
- 第一条完整行程直接展示，其他路线放入原 `tail-alternatives` 折叠区。
  同一路线有多个平台时桌面可并排，手机仍单列；缺另一平台同行程报价时明确提示。
- 卡片只重复平台名称，完整路线提升到行程标题。摘要直接展示价格口径、
  「航段已核对 · 价格未复核」、采集时间与复核操作；没有可比基准时显示
  「无法判断能省多少」，有基准时说明差额、比较对象和同口径参考。
  税费、每人/总价、人数库存、换机场及后续行程影响未核实项不隐藏。
- 详情展开/收起、可识别操作的键盘焦点和结果滚动锚点在重新渲染时保留；
  列表日期筛选不会因暂时无匹配结果被静默清空。空状态按原因提供下一步。
- 首次使用显示「尚未开始查询」，不再误写为「暂无命中结果」；筛选无匹配、
  运行中、历史无报价和任务未保存报价分别显示对应状态。
- 页面可见且无任务运行时每分钟重算过期状态，不发起新的平台查询。
- 手机核心输入、行程、价格、状态和操作采用单列，高级设置继续折叠；
  表单展开时主操作保持可达，结果浏览时不再长期悬浮整组按钮。
  本轮检查 320、390、1280 像素。
- 手机主导航使用「当前功能」原生下拉框，六个工作区均可直接选择并同步状态；
  桌面保留原功能标签，切换工作区不启动、停止或重新查询任务。

## 第二轮：结果前置与决策信息

- 重新打开页面已有结果时折叠查询条件；如果用户在初始化期间已经编辑或点击条件，
  不会强行收起。任务状态和数量保留，继续 / 人工验证 / 失败重试等主要恢复操作可见，
  重新查价和重新查询放进「任务详情与操作」。任务异常原因不随详情一起隐藏。
- 提供「查看结果」按钮，只在用户点击时滚动并把键盘焦点移到结果标题。
  后台刷新不主动跳转，也不展开条件或筛选。
- 列表默认只显示排序和筛选入口。报价状态、日期、价格和只看最新报价放在折叠筛选内，
  入口显示已调整项数量；清除筛选恢复「同一行程只看最新报价」。
- 结果所属航线、出发日期、平台常显；「切换任务 / 查询条件」展开后显示所选任务的
  已记录条件，而不是当前表单。预算、候选、舱位、航司等已记录字段也可查看。
  老任务缺少的条件明确标为未记录，不推断其默认值。
- 表单与所选任务条件分开：使用和提交查询相同的 payload 构建函数比对已记录字段，
  规范化城市代码、航司 / 城市集合及数值；忽略无效的隐藏控制与任务动作模式。
  修改条件只更新提示，不重新查询、不改变结果所属任务。历史模式明确是跨任务结果。
  切换任务开始时清除旧任务身份，避免把新结果套在旧条件下。
- 卡片分开显示「我要乘坐」与「完整购票行程」；明细不足时显示「候选购票行程 ·
  待核实」。实际航段存在换机场时保留两个机场，同时显示换机场警告。
- 可比价差不必展开详情：优先同首段单买价差，再显示符合条件的直飞最低价差，二者
  文案不同。只使用明确可比、金额一致、计价口径已知且航段已核对 / 报价未过期的数据；
  不凭历史行的顶层 savings_amount 宣称省钱。负价差显示「高」，零价差显示「相同」。
- 每人 / 全体乘客总价、含税 / 不含税 / 未确认直接可见；价格和出票仍需复核，行李、
  票规及后续航段影响的未知状态不藏在展开详情后。此轮未改变后端报价计算或平台调用。

## 双平台查询扩展

新增「携程 + 飞猪同时查」，一次操作创建一个父任务并行查询两平台。
平台进度分别展示，结果可按平台筛选；候选条件、飞猪开放发现、预算及恢复语义见
[TAIL_MULTI_PROVIDER.md](TAIL_MULTI_PROVIDER.md)。平台之间不做报价去重或最低价合并。
首次使用默认双平台，已有的本地单平台偏好保留。

## 测试

- `tests/test_tail_result_scope.py`：同条件不同任务隔离、超过 200 条历史时仍可查到
  指定任务、继续任务检查点、旧任务、404、稳定分页、参数校验。
- `tests/test_tail_ui.cjs`：原有报价安全测试，以及状态分区、候选保留、平台设置隐藏、
  展开状态、跨视图迟到响应、断线退避、运行中刷新、POST 丢响应、输入拒绝、
  分页深度、保存白名单、日期筛选保留。
- `tests/browser_tail_smoke.py`：系统 Chrome 下实际加载页面，拦截所有请求到本地
  TestClient。测试本次/历史切换、筛选、复核/恢复请求、设置保存与重载、
  开放/混合请求参数、断线/结果服务故障/恢复、原生校验展开隐藏字段及视口溢出。
  截图和报价均为模拟数据，不能证明携程或飞猪线上查询成功。
- 第二轮新增：表单与结果条件分离、有效参数比对、收起后的筛选计数、价差来源及
  未知 / 过期 / 负数处理、换机场路线、任务操作折叠；浏览器检查默认收起、
  点击跳转的键盘焦点、编辑不发起查询，以及三个视口下刷新不跳回表单。
- P0 决策界面回归：首次/运行/暂停/条件修改的主操作、结果任务归属、首段与实际
  购票行程层级、双平台共享首段但独立报价、不同计价单位仍分组；浏览器核对
  320/390px 核心输入与结果卡为单列，且继续任务仍发送原恢复请求。
- P1 操作流程回归：高级预算归属与摘要、快捷筛选和清除同步、活动任务与旧任务
  并存时的即时归属提示、平台详情展开保持及错误常显；390/320px 使用原生下拉框
  切换到国航实验再返回甩尾，核对六个工作区、状态同步和无横向溢出。
- 可读性回归：完整行程证据一致才并列平台，不同尾段、缺失航段、币种/人数/计价
  单位不同不得合并；检查缺平台提示、平台固定顺序、报价 ID 和展开状态。浏览器核对
  广州与厦门分组、同一厦门的平台报价、结果态紧凑布局和查看方案入口，比较三个视口
  的方案位置；模拟报价不证明真实平台价格或可出票。
- 折叠组件回归：同时展开报价限制、搜索范围和高级控制，在 1280、390、320px
  检查通栏卡片、字段分栏、Bootstrap 箭头、无横向溢出、手机操作栏不遮挡输入项，
  并确认展开与切换平台不会自动发起查询。
