# 国航查询请求保护

2026-11-03：减少重复访问，不提供验证码识别、自动点击或免验证承诺。

## 已实现

- 原生实验 UI、FlyClaw Source/CLI、显式 airchina-probe 共享
  `runtime_dir/airchina_admission` 下的进程间文件锁和 SQLite 状态。
  同一运行目录最多一个国航查询流程执行。等待可取消，计入任务总时限；
  不启动后台重试线程，不承诺严格 FIFO。
- UI 相同规范化请求重复提交时返回原任务 ID，取消/继续操作针对同一个任务；
  不同 UI 任务仍遵守应用既有忙碌拒绝规则，不创建无上限任务队列。
- 使用同一运行目录的并发 Source 请求等待首个查询结束；相同条件成功时命中
  缓存，避免再查。错误不缓存，失败后不会后台重试，之后新的显式请求仍受间隔约束。
- 默认成功参考结果缓存 120 秒，最多 32 个键，间隔默认 30 秒。
  间隔是查询流程启动间隔（不是网页内每条 HTTP 请求的间隔）。
  二者是本地保守参数，不是国航公布的规则。
- 缓存键包含完整 RouteQuery、航班号、入口、会话模式、人工处理及提示授权，
  不跨不同筛选/交互语义复用；原生/FlyClaw 引擎本身不进入键。
- UI 的“每任务重启”和“结果页续查”对照不使用缓存；FlyClaw 独立 Source
  默认使用参考缓存，构造时 `reference_cache=False` 可关闭，但不能绕过暂停或间隔。
  旧诊断 CLI 不使用缓存。
- 缓存命中结果包含 `query_policy.source=cache`、原采集时刻、命中时年龄、
  TTL、未启动浏览器标记。UI 明确显示非实时，历史展示可能已过期。
  Source FlightRecord 同样保留 `query_policy`。不写正式价格快照。
- 验证码、访问限制将全局暂停持久化并清除缓存；人工完成当前页面验证可以
  继续读取当前结果，但不自动解除后续查询暂停。
- first-party HTTP 429 立即暂停。仅额外读取该响应的 `Retry-After` 单一字段，
  支持秒数及 HTTP 日期，取最晚截止时间；不读全量请求头、Cookie 或响应体。
  外部统计资源的 429 和普通 401 不触发这一 HTTP 限流规则。
- 点击“已人工检查，解除国航查询暂停”并确认后才解除本地暂停。
  仍有查询在运行或 Retry-After 未到期时拒绝恢复。解除不发起查询，
  不证明官网验证消失，也不绕过验证码。
- 进程异常退出后若遗留 running 标记，下次检查进入 interrupted 暂停，
  不把旧任务自动重新提交。正常取消等待浏览器清理后释放进程锁。

## UI/API

- `GET /api/experiments/airchina` 增加 `query_policy` 状态及累计计数。
- `POST /api/experiments/airchina/policy/resume` 仅接受 `{"confirmed":true}`。
- `result.query_policy` 区分 live/cache/paused，缓存不伪造当次网络或会话诊断。
- 累计 `browser_runs` 是流程准入次数，不是官网实际提交成功数。实际表单提交
  及页面导航仍需看原有 entry_evidence/network_diagnostics；缓存没有这些记录。

## 边界与验证

不同 runtime_dir、外部手动 Chrome、其他工具或机器不共享本地暂停/锁。
手动登录准备不等于自动查询，不自动解除暂停。缓存不是实时库存、更非可出票价；
不能对缓存的“没触发验证码”计作真实官网查询成功。

不修改指纹、IP、账号或请求签名，不复制验证材料，不扩大浏览器访问权限。
现有同页/持久会话复用逻辑保留，缓存也不打开、刷新或关闭已有成功会话。

离线测试覆盖跨实例/跨进程互斥、同条件复用、TTL、时间间隔、取消清理、
进程异常标记、暂停重启持久化、人工恢复、Retry-After、HTTP 域名边界和 UI
缓存/恢复提示。没有通过真实国航流量评估验证码发生率；不能宣称已解决。
